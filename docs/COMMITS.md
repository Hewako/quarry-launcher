# Как описывать изменения

Описание коммита читают не только разработчики. Любой, кто открыл историю на GitHub,
должен понять, **что поменялось для игрока**. Пишем по-русски и простыми словами.

Подсмотрено у лаунчеров из нашего списка: у Prism Launcher и X Minecraft Launcher список
изменений разбит на «Добавлено / Исправлено / Убрано», у Prism и rust-launcher — короткие
заголовки «одна правка — один коммит». Чего избегаем: «fix bugs», «Update modules» —
такие заголовки ничего не говорят.

## Заголовок (первая строка)

`<Категория>: <что изменилось — простыми словами>` — до ~70 символов, без точки в конце.

| Категория | Когда |
|---|---|
| `Добавлено` | новая возможность |
| `Изменено` | работало, теперь работает иначе |
| `Исправлено` | было сломано, теперь работает |
| `Убрано` | возможность удалена |
| `Безопасность` | закрыта уязвимость или утечка |
| `Служебное` | тесты, документация, сборка — игрок разницы не заметит |

Хорошо:
- `Добавлено: загрузчик модов NeoForge`
- `Исправлено: лаунчер заново скачивал Java при каждом запуске`
- `Убрано: запуск без аккаунта в обычной сборке`

Плохо:
- `fix`, `обновления`, `рефакторинг`
- `Переписан модуль install, добавлен Plan` — игроку непонятно, что изменилось

## Тело

```
Что изменилось:
- одно-два предложения на пункт, как для друга, который играет, но не программирует

Как проверено:
- что запускалось и с каким результатом (или «не проверено на Windows» — честно)

Для разработчиков:
- технические подробности: модули, форматы, новые зависимости (зачем, лицензия)
```

Раздел «Для разработчиков» можно пропустить, если подробности не нужны.

## Список изменений

Каждое заметное для игрока изменение попадает в [CHANGELOG.md](../CHANGELOG.md) в раздел
«Ещё не вышло» — тем же простым языком. При выпуске версии раздел получает номер и дату.

## Шаблон

В репозитории есть шаблон `.gitmessage`. Включить: `git config commit.template .gitmessage`.
